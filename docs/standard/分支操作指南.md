## 1. 环境准备

### 1.1 初始化项目

```bash
# 1. 克隆主项目（包含子模块）
git clone --recursive https://github.com/domonic18/ai-pptist-system.git
cd ai-pptist-system

# 2. 或者分步初始化
git clone https://github.com/domonic18/ai-pptist-system.git
cd ai-pptist-system
git submodule init
git submodule update

# 3. 配置用户信息
git config user.name "Your Name"
git config user.email "your.email@example.com"
```

### 1.2 配置上游仓库（子模块）

```bash
# 进入子模块目录
cd frontend

# 添加上游官方仓库
git remote add upstream https://github.com/domonic18/ai-pptist.git

# 验证远程仓库
git remote -v
# 输出应包含：
# origin    https://github.com/domonic18/ai-pptist.git (fetch)
# origin    https://github.com/domonic18/ai-pptist.git (push)
# upstream  https://github.com/domonic18/ai-pptist.git (fetch)
# upstream  https://github.com/domonic18/ai-pptist.git (push)
```

### 1.3 设置默认分支

```bash
# 主目录设置
git config init.defaultBranch develop

# 子模块设置
cd frontend
git config init.defaultBranch develop
```

## 2. 主目录分支操作

### 2.1 开发新功能

#### 步骤1：创建功能分支

```bash
# 确保在 develop 分支
git checkout develop
git pull origin develop

# 创建功能分支（命名规范：feature/<模块>-<功能描述>）
git checkout -b feature/banana-generation
```

#### 步骤2：开发功能

```bash
# 进行代码修改
# ...

# 查看修改状态
git status

# 暂存文件
git add backend/app/services/banana_generation_service.py
git add backend/app/schemas/banana_generation.py

# 提交代码（遵循提交规范）
git commit -m "feat(banana): 添加图片生成服务

实现完整的图片生成流程，包括任务管理、状态跟踪和结果返回。

主要变更:
- 添加 BananaGenerationService 服务类
- 实现 generate_batch_slides 批量生成方法
- 实现 get_generation_status 状态查询方法
- 添加相关的 Pydantic schema 定义

Closes #123"
```

#### 步骤3：推送到远端

```bash
# 推送功能分支到远端
git push origin feature/banana-generation

# 如果是首次推送，设置上游跟踪
git push -u origin feature/banana-generation
```

#### 步骤4：创建 Pull Request

```bash
# 在 GitHub 上创建 PR
# 或者使用 GitHub CLI：
gh pr create \
  --title "feat(banana): 添加图片生成服务" \
  --body "实现了完整的图片生成流程..." \
  --base develop \
  --head feature/banana-generation
```

#### 步骤5：代码审查和合并

```bash
# PR 审查通过后，在本地合并
git checkout develop
git pull origin develop
git merge --no-ff feature/banana-generation

# 推送更新
git push origin develop

# 删除已合并的功能分支
git branch -d feature/banana-generation
git push origin --delete feature/banana-generation
```

### 2.2 修复 Bug

#### 修复非紧急 Bug

```bash
# 从 develop 创建修复分支
git checkout develop
git pull origin develop
git checkout -b fix/ocr-coordinate-error

# 修复 Bug
# ...

# 提交修复
git add .
git commit -m "fix(ocr): 修复坐标转换使用真实图片尺寸

修复前端坐标转换时使用元素显示尺寸而非真实图片尺寸的问题。

问题:
- imageSize 使用 1000x562.5（元素尺寸）而非 1920x1080（真实尺寸）
- 导致 scale = 1，坐标转换失效

解决:
- 后端返回 metadata 包含 image_width 和 image_height
- 前端优先使用 metadata 中的真实尺寸

Fixes #124"

# 推送并创建 PR
git push -u origin fix/ocr-coordinate-error
gh pr create --title "fix(ocr): 修复坐标转换..." --base develop
```

#### 紧急修复（hotfix）

```bash
# 从 master 创建 hotfix 分支
git checkout master
git pull origin master
git checkout -b hotfix/security-fix

# 修复紧急问题
# ...

# 提交修复
git add .
git commit -m "hotfix: 修复API密钥泄露安全漏洞

紧急修复 API 密钥在日志中暴露的问题。

修复:
- 移除日志中的敏感信息
- 添加敏感信息过滤中间件

Security: 严重"

# 推送并创建 PR 到 master
git push -u origin hotfix/security-fix
gh pr create \
  --title "hotfix: 修复API密钥泄露安全漏洞" \
  --base master \
  --label "critical,security"

# PR 审查通过后合并到 master
# 然后合并回 develop
git checkout master
git pull origin master
git checkout develop
git merge master
git push origin develop

# 删除 hotfix 分支
git branch -d hotfix/security-fix
git push origin --delete hotfix/security-fix
```

### 2.3 发布新版本

#### 步骤1：创建发布分支

```bash
# 从 develop 创建发布分支
git checkout develop
git pull origin develop
git checkout -b release/v1.2.0

# 更新版本号
# 编辑 version.txt 或相关配置文件
echo "1.2.0" > version.txt

# 提交版本更新
git add version.txt
git commit -m "chore: bump version to 1.2.0"
```

#### 步骤2：发布测试

```bash

# ...

# 提交修复
git add .
git commit -m "fix: 修复发布前发现的bug"
```

#### 步骤3：合并到 master

```bash
# 切换到 master
git checkout master
git pull origin master

# 合并发布分支
git merge --no-ff release/v1.2.0

# 创建版本标签
git tag -a v1.2.0 -m "Release version 1.2.0

主要功能:
- Banana图片生成功能

git push origin master
git push origin v1.2.0
```

#### 步骤4：合并回 develop

```bash
git checkout develop
git merge --no-ff release/v1.2.0
git push origin develop

# 删除发布分支
git branch -d release/v1.2.0
git push origin --delete release/v1.2.0
```

## 3. 子模块分支操作

### 3.1 同步上游官方库

#### 完整同步流程

```bash
# 1. 进入子模块目录
cd frontend

# 2. 确保在 master 分支
git checkout master
git pull origin master

# 3. 获取上游更新
git fetch upstream

# 4. 查看上游最新提交
git log upstream/master --oneline -5

# 5. 创建同步分支（命名规范：sync/upstream-YYYYMMDD）
git checkout -b sync/upstream-$(date +%Y%m%d)

# 6. 合并上游代码
git merge upstream/master

# 7. 如果有冲突，手动解决
# git status  # 查看冲突文件
# 编辑冲突文件，解决冲突
# git add <resolved-files>
# git commit -m "sync: 解决与上游的合并冲突"

# 8. 推送同步分支
git push -u origin sync/upstream-$(date +%Y%m%d)

# 9. 在 GitHub 上创建 PR
# 从 sync/upstream-20241228 -> master
# PR 标题：sync(upstream): 同步官方库最新代码到 master
# PR 描述：
#   同步内容：
#   - 合并 upstream/master 最新提交
#   - 解决冲突 xxx
#   - 更新依赖版本 xxx

# 10. PR 审查通过后合并到 master
# 在 GitHub 上点击 "Merge pull request"

# 11. 更新本地 master
git checkout master
git pull origin master

# 12. 创建更新 develop 的 PR
# 从 master -> develop

# 13. 删除同步分支（可选）
git branch -d sync/upstream-$(date +%Y%m%d)
git push origin --delete sync/upstream-$(date +%Y%m%d)
```

```bash
# 创建 PR 到 develop

  --title "feat(banana): 集成Banana生成服务" \
```

## 4. 团队协作操作

### 4.1 分配任务

```bash
# 1. 在 GitHub Issues 中查看任务
gh issue list

# 2. 领取任务
gh issue edit 123 --add-assignee "your-username"

# 3. 创建对应的功能分支
git checkout develop
git checkout -b feature/issue-123-user-auth
```

### 4.2 代码审查

```bash
# 1. 查看待审查的 PR
gh pr list --state open --reviewer "your-username"

# 2. 审查 PR
gh pr view 456

# 3. 添加审查评论
gh pr review 456 --comment "需要添加单元测试"

# 4. 批准 PR
gh pr review 456 --approve

# 5. 请求修改
gh pr review 456 --request-changes "存在安全问题..."
```

### 4.3 解决冲突

#### 合并时冲突

```bash
# 1. 拉取最新代码
git checkout feature/your-feature
git pull origin feature/your-feature

# 2. 合并目标分支
git checkout develop
git pull origin develop
git merge feature/your-feature

# 3. 如果有冲突
# Git 会提示冲突文件
# 编辑冲突文件，查找 <<<<<<<, =======, >>>>>>> 标记

# 4. 解决冲突后标记为已解决
git add <resolved-files>

# 5. 完成合并
git commit -m "merge: 合并feature/your-feature到develop，解决冲突"

# 6. 推送
git push origin develop
```

#### 子模块冲突

```bash
# 1. 查看子模块状态
git submodule status

# 2. 进入子模块
cd frontend

# 3. 重置到正确的分支
git checkout integration/ai-pptist
git pull origin integration/ai-pptist

# 4. 返回主目录
cd ..

# 5. 更新子模块引用
git add frontend
git commit -m "chore: 解决子模块冲突"
```

## 5. 常见场景操作

### 5.1 临时保存工作

```bash
# 1. 保存当前工作现场
git stash save "临时保存：添加登录功能"

# 2. 切换到其他分支
git checkout develop

# 3. 完成其他工作后返回
git checkout feature/login

# 4. 恢复工作现场
git stash pop

# 5. 查看所有 stash
git stash list

# 6. 删除特定 stash
git stash drop stash@{0}
```

### 5.2 撤销提交

```bash
# 撤销最后一次提交（保留修改）
git reset --soft HEAD~1

# 撤销最后一次提交（丢弃修改）
git reset --hard HEAD~1

# 撤销多次提交
git reset --hard HEAD~3

# 撤销已推送的提交（谨慎使用）
git revert <commit-hash>
git push origin feature/your-feature
```

### 5.3 查看历史

```bash
# 查看提交历史
git log --oneline --graph --all

# 查看分支历史
git log --oneline --graph --all --decorate

# 查看特定文件历史
git log --oneline backend/app/services/banana_generation_service.py

# 查看提交详情
git show <commit-hash>

# 查看分支差异
git diff master...develop

# 查看文件差异
git diff master backend/app/services/banana_generation_service.py
```

### 5.4 清理分支

```bash
# 查看所有分支
git branch -a

# 删除已合并的本地分支
git branch --merged | grep -v "\*" | xargs -n 1 git branch -d

# 删除未合并的本地分支（强制）
git branch -D feature/old-feature

# 删除远端分支
git push origin --delete feature/old-feature

# 清理已删除的远端分支引用
git remote prune origin
```

## 6. 故障排查

### 6.1 子模块问题

#### 子模块显示为 detached HEAD

```bash
# 查看子模块状态
git submodule status

# 进入子模块
cd frontend

# 检查当前分支
git branch

# 切换到正确的分支
git checkout integration/ai-pptist

# 返回主目录并更新子模块引用
cd ..
git add frontend
git commit -m "chore: 修复子模块detached HEAD状态"
```

#### 子模块更新失败

```bash
# 强制更新子模块
git submodule update --remote --merge frontend

# 或者删除子模块重新初始化
git submodule deinit frontend
rm -rf .git/modules/frontend
git submodule update --init frontend
```

### 6.2 远端仓库问题

#### 推送被拒绝

```bash
# 拉取远端更新
git pull origin develop

# 如果有冲突，解决后推送
# ... 解决冲突 ...
git push origin develop

# 或者强制推送（谨慎使用）
git push origin develop --force-with-lease
```

#### 远端分支不存在

```bash
# 确保远端仓库是最新的
git fetch origin

# 查看所有远端分支
git branch -r

# 创建并推送新分支
git checkout -b feature/new-feature
git push -u origin feature/new-feature
```

### 6.3 合并问题

#### 合并冲突

```bash
# 1. 查看冲突文件
git status

# 2. 编辑冲突文件
# 找到冲突标记：
# <<<<<<< HEAD
# 当前分支的代码
# =======
# 合并分支的代码
# >>>>>>> feature/other-feature

# 3. 选择保留的代码，删除冲突标记

# 4. 标记为已解决
git add <resolved-files>

# 5. 完成合并
git commit

# 6. 如果想放弃合并
git merge --abort
```

#### 回退合并

```bash
# 如果合并有问题，回退
git reset --hard HEAD~1

# 或者使用 revert（保留历史）
git revert -m 1 HEAD
```

## 7. 实用脚本

### 7.1 快速开始新功能

```bash
#!/bin/bash
# quick-start-feature.sh

FEATURE_NAME=$1
if [ -z "$FEATURE_NAME" ]; then
  echo "Usage: ./quick-start-feature.sh <feature-name>"
  exit 1
fi

echo "🚀 Starting new feature: $FEATURE_NAME"

# 更新 develop
git checkout develop
git pull origin develop

# 创建功能分支
git checkout -b feature/$FEATURE_NAME

echo "✅ Feature branch 'feature/$FEATURE_NAME' created!"
echo "📝 Remember to follow commit conventions:"
echo "   feat(scope): description"
echo "   fix(scope): description"
```

使用方式：
```bash
chmod +x quick-start-feature.sh
./quick-start-feature.sh banana-generation
```

### 7.2 同步上游脚本

```bash
#!/bin/bash
# sync-upstream.sh

echo "🔄 Syncing with upstream..."

cd frontend
git fetch upstream
DATE=$(date +%Y%m%d)
git checkout -b sync/upstream-$DATE
git merge upstream/master

echo "✅ Sync branch created: sync/upstream-$DATE"
echo "📝 Please resolve conflicts if any, then:"
echo "   git push origin sync/upstream-$DATE"
echo "   gh pr create --base master --title 'sync(upstream): 同步上游代码'"
```

### 7.3 清理脚本

```bash
#!/bin/bash
# clean-branches.sh

echo "🧹 Cleaning up merged branches..."

# 清理已合并的本地分支
git branch --merged | grep -v "\*" | grep -v "master\|develop" | xargs -n 1 git branch -d

echo "✅ Local branches cleaned"

# 清理已删除的远端分支引用
git remote prune origin

echo "✅ Remote branch references pruned"
```
